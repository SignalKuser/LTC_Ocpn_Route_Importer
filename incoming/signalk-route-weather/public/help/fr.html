Prérequis

OpenCPN, version 32 bits pour Windows

Signal K, Raspberry Pi ARM64

Préparation de Signal K

Le module Signal K (LTC_Ocpn_Route_Importer) peut utiliser des fichiers GPX locaux stockés sous Windows ou sur le Raspberry Pi.

Il est toutefois plus pratique de tracer la route dans OpenCPN et de l’envoyer à la volée à Signal K.

Créer dans Signal K un compte « opencpn » avec les droits de lecture et d’écriture, puis exécuter la commande suivante dans le terminal du Pi pour créer un jeton.

signalk-generate-token -u opencpn -e 1y -s ~/.signalk/security.json

Cela permet à Signal K d’accepter ensuite les données d’OpenCPN. Conserver le jeton ou le copier et l’enregistrer pour une utilisation ultérieure.

Installation de LTC_Ocpn_Route_Importer

Placer de préférence le script PowerShell et le module dans le même dossier, puis lancer le script depuis ce dossier.

Le script trouve automatiquement le module et le dossier des modules Signal K sur le Pi, puis y installe le module.

Si Signal K est déjà en cours d’exécution, le redémarrer, puis activer le module dans la configuration des modules Signal K (« Enable »).

Le module est accessible sous « Webapps ».

Installations supplémentaires

Pour les fournisseurs de données maillées, le Pi a besoin de « grib_get » pour lire les fichiers GRIB. Avec une connexion à Internet, exécuter ces commandes dans le terminal du Pi.

sudo apt-get update
sudo apt-get install libeccodes-tools

Pour DWD, exécuter également la commande suivante.

sudo apt-get install bzip2

Met Office UKV (NetCDF) requiert python3-gdal sur le Pi.

sudo apt-get install python3-gdal

Pour accéder à ces données pour la Suède, installer ce module dans Signal K.

Configuration d’OpenCPN

L’import direct de routes depuis OpenCPN nécessite le module externe Signal K Route Sender.

Version GitHub contenant Signal K Route Sender

Dans Assets, télécharger et décompresser l’archive RAR. Dans OpenCPN, installer le paquet SignalKRouteSender-*.tar.gz correspondant via Plugins → Importer un plugin, puis activer le module.

Sous Options → Connexions, configurer et activer la connexion Signal K. Si le serveur exige une authentification, saisir le jeton Signal K dans cette connexion sous Avancé → Auth Token. Le module utilise cette connexion.

Utilisation d’OpenCPN

Tracer une route dans OpenCPN. Faire un clic droit sur un point de route et, de préférence, donner un nom à la route dans le menu contextuel « Route / Propriétés ».

Sélectionner ensuite « Envoyer à Signal K » sous « Route ».

La route GPX est alors envoyée à Signal K et disponible à l’adresse /signalk/v2/api/resources/routes.

D’autres modules Signal K, comme Freeboard-SK et Binnacle, y enregistrent aussi leurs routes. Ces routes peuvent également être utilisées avec LTC_Ocpn_Route_Importer.

Utilisation de LTC_Ocpn_Route_Importer

Sur la page 1, choisir Signal K, GPX (Win) ou GPX (Pi) comme source de la route. GPX (Win) ouvre le sélecteur de fichiers Windows et permet de sélectionner plusieurs fichiers. Dans GPX (Pi), saisir le chemin, cliquer sur Enregistrer le dossier, puis choisir un fichier dans la liste. Si le fichier GPX contient plusieurs routes, chacune peut être sélectionnée séparément. Les points de route s’affichent en dessous. Sélectionner un fournisseur météo sous « Fournisseur ». Les fournisseurs fonctionnent de différentes façons. Certains fournissent la météo pour une heure et des coordonnées données. Pour les autres, des fichiers GRIB sont téléchargés automatiquement et les coordonnées des points de route sont associées aux données du fichier GRIB pour déterminer la météo.

Télécharger la météo

La météo est téléchargée, associée aux points de route selon l’heure et enregistrée immédiatement. La sélection se fait sous « Prévision enregistrée ».

Prévision enregistrée

Choix entre plusieurs versions d’un même fournisseur ou de fournisseurs différents. Les prévisions enregistrées peuvent y être supprimées.

Cela peut être utile pour comparer différents fournisseurs sur une même route.

SOG prévue

C’est la vitesse fond théorique retenue lorsque le bateau est à l’arrêt, pour la planification au port.

Après avoir évalué le vent, saisir ici la vitesse fond prévue.

Cette valeur sert de point de départ au calcul de l’ETA.

Calcul de l’ETA

GPS, SOG, COG

À activer de préférence pour l’ETA. Cette option utilise la position et la vitesse fond réelle, qui tient déjà compte du vent et du courant.

Lorsque GPS, SOG et COG sont actifs et que l’ETA repose sur les données GPS, l’application utilise la SOG mesurée et le COG pour calculer la part de cette vitesse vers le prochain point de route. Pour les tronçons suivants, l’application utilise la source de vitesse adaptée ou la SOG prévue.

Le courant à la position actuelle est déjà pris en compte dans la vitesse fond mesurée.

Lorsque le vecteur de courant est désactivé, l’application ne calcule pas de prévision de courant supplémentaire pour les tronçons suivants.

Si la SOG GPS est inutilisable et qu’aucune autre source de vitesse ne s’applique, l’application utilise la SOG prévue.

Pour estimer le courant à partir des mesures à bord, les deux mouvements doivent être exprimés sous forme de vecteurs.

  • La SOG et le COG indiquent la vitesse et la direction du déplacement du bateau par rapport au fond.
  • La STW et la direction réelle du déplacement dans l’eau indiquent le mouvement du bateau par rapport à l’eau.

Le cap peut servir d’approximation. La dérive latérale due au vent rend l’estimation moins précise.

La différence entre ces vecteurs donne le courant estimé. La STW seule ne suffit pas.

Vecteur de courant

L’application utilise HARMONIC et HARMONIC.IDX pour l’ETA lorsque « Vecteur de courant » est activé, que des données adaptées sont disponibles et que la vitesse du tronçon provient de la SOG moteur, de la polaire LTC, de la STW ou de la SOG prévue.

Pour trouver les données adaptées, l’application vérifie dans les fichiers IDX si les coordonnées des points de route correspondent. Il est préférable de regrouper les fichiers IDX dans un même dossier. L’application cherche automatiquement les fichiers IDX adaptés dans les sous-dossiers et les indique pour chaque point de route. Plusieurs fichiers IDX peuvent ainsi servir pour une même route.

Fichiers IDX pour l’Europe, la mer du Nord, la baie Allemande et la mer Baltique, entre autres https://github.com/SignalKuser?tab=repositories

Pour chaque tronçon concerné, elle consulte le courant au point d’arrivée du tronçon à l’heure d’arrivée estimée provisoirement.

Elle calcule les composantes du courant le long du tronçon et perpendiculairement à celui-ci, puis corrige l’ETA en conséquence. Une mesure de la STW est facultative.

Si un tronçon utilise la SOG GPS mesurée, l’application n’applique pas la correction IDX sur ce tronçon.

Lors du chargement d’une route, elle peut toutefois vérifier et afficher la disponibilité de stations de courant adaptées. Cette vérification seule ne modifie pas l’ETA.

STW – Speed Through Water

En l’absence de GPS/SOG, la STW peut servir de vitesse de référence pour l’ETA. Le vecteur de courant permet alors d’estimer la vitesse fond. Sans position GPS, la progression réelle sur la route reste inconnue.

AWS – Apparent Wind Speed

Pour l’ETA, le vent actuel fourni par Signal K est pris comme hypothèse pour les tronçons à venir. En l’absence de vent vrai, l’application le déduit de l’AWS, de l’AWA, de la vitesse du bateau et de sa route. La polaire LTC est lue sans être modifiée.

Utiliser le cap vrai

Lorsque l’option est activée, l’application oriente l’AWS et l’AWA à l’aide de « navigation.headingTrue ». Sinon, elle utilise le COG comme approximation.

La STW disponible sert au calcul du vent à partir de l’AWS et de l’AWA. L’option « STW – Speed Through Water » détermine uniquement si la STW peut aussi servir de vitesse de référence pour l’ETA.

Si Signal K ne dispose d’aucune source de cap, le COG sert d’approximation.

Moteur marche/arrêt

Lorsque « Moteur marche/arrêt » est activé, l’application utilise la SOG moteur comme base pour tous les tronçons restants.

Cette valeur est prioritaire sur la SOG GPS, la polaire LTC, la STW et la SOG prévue.

Si le vecteur de courant est aussi activé et que des fichiers IDX adaptés sont disponibles, l’application corrige la SOG moteur pour chaque tronçon.

Données de polaire

Les polaires déterminent la vitesse estimée pour chaque tronçon lorsque l’option est activée et qu’un fichier adapté est sélectionné. L’application utilise la vitesse du vent vrai attendue (TWS) et l’angle du vent par rapport au tronçon (TWA). Elle estime ainsi la vitesse de progression du bateau vers le prochain point de route. Face au vent, le calcul peut aussi tenir compte du louvoyage.

Exemple. Un tronçon de 20 milles nautiques à une SOG prévue de 5 kn dure environ 4 heures. Si, à cause du vent de face, la polaire indique une progression de seulement 4 kn vers le point d’arrivée, l’application compte 5 heures. Cela décale aussi les ETA des points suivants et, le cas échéant, les heures des prévisions affichées.

La SOG moteur est prioritaire si le moteur est activé. En mode voile, une polaire utilisable est prioritaire sur la SOG GPS, la STW et la SOG prévue.

La précision de l’ETA dépend donc aussi de la fidélité avec laquelle la polaire choisie représente le bateau.

Rayon du point de route

Un point de route est considéré comme atteint dès que le bateau entre dans le rayon défini.

Distance et relèvement vers le prochain point de route

La position actuelle peut être éloignée de la route.

La distance et le relèvement vers le point de route le plus proche s’affichent ici.

Une fois ce point atteint, tous les points de route précédents sont considérés comme passés.

Pondération du vent

Le vent affiché provient du fournisseur et correspond à une prévision. Le vent mesuré à bord est beaucoup plus précis et est donc pris en compte. Plus l’éloignement augmente dans l’espace et dans le temps, moins le vecteur du vent mesuré à bord (vitesse et direction) pèse dans le calcul, jusqu’à n’avoir que peu d’effet. Son poids augmente à l’approche d’un point de route.

Portée du vent mesuré à bord

Le curseur comporte 15 niveaux. Le troisième est sélectionné par défaut. Plus la distance le long de la route et la durée de trajet estimée augmentent, plus la prévision compte. La limite la plus avancée en proportion détermine la pondération. Dès qu’une des deux limites est atteinte, la prévision compte pour 100 % si elle est disponible et activée.

  1. 0,5 NM ou 10 min
  2. 1 NM ou 20 min
  3. 2 NM ou 30 min
  4. 3 NM ou 45 min
  5. 5 NM ou 60 min

Du niveau 6 au niveau 15, chaque cran ajoute 2 NM et 24 minutes. Le niveau 15 atteint 25 NM ou 5 heures.

Si la vitesse du vent combiné est inférieure au tiers de la somme des deux vitesses pondérées, la source dont le poids est le plus élevé fournit sa vitesse et sa direction du vent pour ce point de route. À poids égal, le vent mesuré à bord est prioritaire.

Vérifier les chemins Signal K

Rechercher le chemin sous Data → Browser. Pour les données du bateau, Context doit indiquer self. Value, Timestamp et Source indiquent la valeur, son horodatage et sa source.

  • navigation.position — Position GPS pour la progression, la distance et le relèvement vers le prochain point
  • navigation.speedOverGround — Vitesse fond (SOG) pour l’ETA et comme solution de repli à la STW pour calculer le vent
  • navigation.courseOverGroundTrue — Route fond vraie (COG) pour l’ETA et comme approximation de l’orientation du bateau
  • navigation.speedThroughWater — Vitesse surface (STW) pour l’ETA et le calcul du vent
  • navigation.headingTrue — Cap vrai si l’option est activée
  • environment.wind.speedApparent — Vitesse du vent apparent (AWS)
  • environment.wind.angleApparent — Angle du vent apparent (AWA) par rapport à l’étrave
  • environment.wind.speedTrue — Vitesse du vent vrai (TWS)
  • environment.wind.directionTrue — Direction du vent vrai par rapport au nord vrai

Points d’accès de l’API Signal K

Ajouter le chemin à l’adresse du serveur Signal K pour l’ouvrir dans un navigateur.

  • /signalk/v1/api/vessels/self/navigation/speedThroughWater — Exemple de donnée du bateau en m/s
  • /signalk/v2/api/vessels/self/navigation/course — Route active, prochain point et sens de parcours
  • /signalk/v2/api/resources/routes — Routes enregistrées dans Signal K
  • /signalk/v2/api/weather/_providers — Fournisseurs météo enregistrés
  • /signalk/v2/api/weather/forecasts/point — Prévision pour les coordonnées d’un point de route

Export direct depuis qtVlm

Sur la page 2, activer la réception qtVlm. Dans qtVlm, ouvrir Échangeur de données → Envoyer, choisir le type et l’élément à transférer, puis cliquer sur Envoyer. Le Raspberry Pi détecte automatiquement l’émetteur. La page 2 affiche les éléments importés et les erreurs éventuelles.

Les deux appareils doivent être sur le même réseau local, par exemple le point d’accès Wi-Fi du Pi du bateau. Le pare-feu doit autoriser la découverte sur le port UDP 5555 et les connexions du Pi à qtVlm sur le port TCP 5555.

  • Les routes apparaissent dans la source de routes Signal K.
  • Les parcours apparaissent comme routes dans la source Signal K.
  • Les POI sont enregistrés comme points de route Signal K.
  • Les archives de POI sont enregistrées comme points de route Signal K avec le nom de l’archive.
  • Les ensembles de barrières sont disponibles en GeoJSON sur la page 2.
  • Les traces archivées sont disponibles comme fichiers GPX dans GPX (Pi).
  • Les fichiers GRIB apparaissent dans le sélecteur de fichiers GRIB.

L’import des routes et des POI qtVlm nécessite Python 3 sur le Pi. Pour le GPS et le vent, saisir l’adresse IP du Pi et le port 10110 sous Connexions NMEA → Entrants → Sources réseau → TCP. L’adresse par défaut du Pi du bateau est 10.42.0.1. Signal K doit émettre les phrases NMEA 0183 nécessaires.

Fichier GRIB personnel

  1. Sur la page 2, cocher Activer la réception qtVlm. Envoyer le fichier GRIB depuis qtVlm. Le fichier reçu s’affiche sur la page 2.
  2. Sur la page 1, choisir Fichier GRIB personnel dans la liste des fournisseurs, puis cliquer sur Charger un fichier GRIB sous la prévision enregistrée.
  3. Choisir le fichier dans Fichiers GRIB enregistrés, puis cliquer sur Utiliser le fichier.
  4. Sélectionner les champs souhaités dans Données supplémentaires, puis cliquer à droite sur Analyser le GRIB.
  5. Afficher les valeurs supplémentaires dans le tableau via Colonnes supplémentaires.

Si vous disposez déjà d’un fichier, commencez à l’étape 2. La boîte de dialogue permet de téléverser un fichier, de saisir un chemin absolu sur le Pi ou d’utiliser un lien de téléchargement HTTP(S) direct. Donner un nom au lien pour l’enregistrer comme source.

Sur la page 2, Import direct qtVlm affiche les fichiers GRIB enregistrés avec la date et l’heure d’importation. Pour retirer un fichier, cliquer à droite sur Supprimer et confirmer.

Le fichier et la prévision calculée sont disponibles hors ligne. L’analyse sur le Pi nécessite libeccodes-tools.
